# Markdown 阅读编辑器开发规范

版本：0.7（Windows 已有打开关联的升级兼容）  
制定日期：2026-11-19  
更新日期：2026-11-21  
当前状态：首版功能已实现，实际检查结果与剩余人工验收项见 `docs/验收记录.md`。

## 1. 产品定位

开发一款离线优先、Windows 优先的桌面 Markdown 阅读编辑器，让用户能够轻松打开、阅读、编辑和保存本地 Markdown 文件。

产品的三个优先级依次为：文件与内容可靠、阅读编辑顺手、界面简洁美观。

本规范中的技术选型与首版范围作为开发基线。当前环境为 Node.js 22 LTS 与 Electron 45，具体版本由锁文件固定；打包与运行验证结果记录在验收文档中。

## 2. 首版功能范围

| 模块     | 首版要求                                                            | 验收要点                                               |
| -------- | ------------------------------------------------------------------- | ------------------------------------------------------ |
| 文件操作 | 新建、打开、另存为、保存；支持 `.md`、`.markdown`                   | 保存后重新打开，内容一致；取消文件对话框不改变当前文档 |
| 阅读模式 | 居中排版、适当行宽、文章目录、标题跳转                              | 长文清晰易读，代码和表格不会撑破页面                   |
| 编辑模式 | Markdown 语法高亮、行号、撤销重做、查找替换                         | 中文输入、粘贴、撤销和替换均正常                       |
| 分屏模式 | 编辑器与预览并排，预览随输入更新，可拖动分隔线                      | 普通文档编辑流畅，调整宽度不丢失内容                   |
| Markdown | CommonMark 基础语法、GFM 表格、任务列表、删除线、自动链接、围栏代码 | 统一样例集在阅读和分屏预览中表现一致                   |
| 阅读辅助 | 代码高亮、代码复制、图片、链接、字数与保存状态                      | 复制得到原始代码，失效图片有清晰占位                   |
| 外观设置 | 浅色、深色、跟随系统；阅读字号和编辑字号                            | 设置重启保留，主题切换不丢失光标和内容                 |
| 内容保护 | 未保存提示、恢复草稿、外部修改冲突处理                              | 取消关闭、写入失败和异常退出均不静默丢失内容           |
| 桌面交付 | Windows x64 安装包                                                  | 安装后可离线启动并完成打开、编辑、保存流程             |

应用支持多文档标签。打开或新建文件时增加标签，不替换其他标签；顶部可切换和关闭文件，同一磁盘文件重复打开时激活已有标签。文件对话框支持多选，支持从资源管理器拖入一个或多个 `.md` / `.markdown` 文件；不支持的文件不打开，也不能导致窗口跳转。

Windows 将墨页设为默认打开方式后，双击 `.md` / `.markdown` 必须直接打开该文件，不能只显示欢迎页。应用只保留一个实例与主窗口；运行中再次双击文件时，在已有窗口增加并激活标签，最小化窗口会恢复。重复打开同一文件激活已有标签，保留未保存正文、撤销记录与视图；已有标签不受新文件影响。启动、草稿恢复确认或其他操作尚未完成时，外部打开请求排队等待，不丢弃请求。启动参数只接收受支持的本地文件路径，不把可执行文件、开发入口或 Chromium 选项作为文档；中文、空格、多个文件、相对路径与接收方工作目录不同均须正确处理。读取失败时提示错误，仍保留当前标签和未保存内容。安装包注册两种扩展名的打开能力，默认程序由用户在 Windows 中选择。

Windows 可能将用户选择的默认程序记录为 `Applications/墨页.exe`。安装与升级必须同时更新墨页自身的 `Applications` 打开命令与 `Moyan.Markdown` 文件类型关联，避免同名程序仍启动旧免安装目录。可执行文件路径与文件参数均使用独立引号；保留系统维护的用户默认选择。卸载只清理仍指向自身安装目录的应用注册，不能删除后续版本或其他位置接管的注册。验收必须通过 Windows 实际关联查询与默认 Shell 打开临时 Markdown 文件，分别确认首次读取和运行中新增标签，不能仅以直接启动 exe 传参作为默认打开已通过的依据。

每个标签独立保留正文、撤销重做、编辑位置、滚动位置、显示模式和保存状态。关闭单个标签时只检查该文件，退出应用时逐个检查有实际修改的文件；取消退出后保留所有尚未关闭的标签。空白新文档、仅进入编辑模式、光标移动、查找、主题变化，以及撤销或手动还原至保存内容，均不标记未保存、不弹出保存确认。

标签右键菜单包含“打开所在文件夹”“关闭其他标签”“关闭所有标签”。操作针对右键点中的标签；打开文件夹在资源管理器中定位该文件，新建且未落盘的文档禁用此项。只有一个标签时禁用“关闭其他标签”。批量关闭先确认所有目标的实际修改，再一次移除标签；取消、保存失败或另存为取消时不移除任何目标标签，已获用户确认完成的保存或重新载入仍保留。关闭其他标签后激活保留的标签，关闭全部后回到欢迎页。右键与键盘菜单键 / Shift+F10 均可使用，不增加常驻界面占位。

以下功能放到后续版本：文件夹工作区、云同步、账户、协作、插件系统、AI 功能、PDF/Word 导出、所见即所得编辑、公式、Mermaid、脚注和脚本执行。滚动同步也作为后续增强；首版仅要求预览实时更新。

## 3. 交互与视觉规范

### 3.1 窗口与布局

- 初次启动展示欢迎空态，提供“新建文档”和“打开文件”。
- 顶部提供文件操作与“阅读 / 编辑 / 分屏”模式切换，文档操作不依赖悬浮按钮。
- 顶部使用一行约 38px 的紧凑工具栏与一行约 30px 的文件标签；移除重复文件名、面包屑、独立文件信息栏与面板说明条。格式操作合并到工具栏，图标按钮保留可访问名称、快捷键提示及至少 24px 的点击区域。
- 目录栏默认宽度约 180px，保持可收起；底部状态栏约 22px。正文阅读字号不随控件缩小，浅色、深色和最小窗口均需检查布局与常用操作可达性。
- 左侧为可折叠目录，中间为内容区，底部显示文件状态、字数、光标位置和编码。
- 无历史偏好时，打开已有文件默认阅读模式，新建文档默认编辑模式；后续尊重用户保存的模式偏好。
- 设计基准窗口为 1280 × 800，最小窗口为 900 × 600；空间不足时收起目录。
- 分屏时两侧均设最小宽度；窗口不足以容纳时切换为单栏并给出明确状态。

### 3.2 阅读体验

- 正文默认 16px，行高约 1.75，内容最大宽度约 800px，左右保留呼吸空间。
- 阅读字号支持 14–24px 调整；中英文使用系统字体组合，代码使用等宽字体。
- 标题有明确层级，段落间距稳定；引用、列表、链接和分隔线风格统一。
- 长表格和长代码块在容器内横向滚动，普通正文自动换行。
- 图片保持比例，不超出内容宽度；标题锚点支持重复标题和中文标题。
- 首版不执行原始 HTML，按文本展示；支持范围外的语法不得伪装成已支持。

### 3.3 编辑体验

- 使用成熟编辑器组件，避免用普通文本框自行实现复杂编辑行为。
- 正确处理中文输入法组合过程，输入中不抢焦点、不移动光标、不提前提交快捷操作。
- 切换阅读、编辑和分屏模式时保留文档内容、撤销历史和编辑位置。
- 查找支持大小写与全词选项；替换全部应能够一次撤销。正则查找暂不纳入首版。
- 状态栏持续显示“已保存”“未保存”或“保存失败”，不能只依赖颜色区分。
- 字数统计口径固定：汉字逐字计数，英文与数字按词计数，空白和 Markdown 标记不计入；混合文本规则由固定样例验证。

### 3.4 快捷键与可访问性

| 快捷键          | 行为                                 |
| --------------- | ------------------------------------ |
| Ctrl+N          | 新建文档                             |
| Ctrl+O          | 打开文件                             |
| Ctrl+S          | 保存                                 |
| Ctrl+Shift+S    | 另存为                               |
| Ctrl+F          | 查找                                 |
| Ctrl+H          | 替换                                 |
| Ctrl+Z / Ctrl+Y | 撤销 / 重做                          |
| Ctrl+Shift+P    | 循环切换阅读、编辑、分屏             |
| Esc             | 关闭当前弹层或查找栏，焦点回到原位置 |

- 所有按钮具有可访问名称和可见焦点；主要流程可以仅用键盘完成。
- 正文与背景对比度至少满足 WCAG AA 普通文本 4.5:1。
- 弹窗打开时正确管理焦点，关闭后恢复焦点；工具提示不承载唯一的重要信息。
- 图标配合文字或工具提示；错误信息说明发生了什么以及可采取的操作。

## 4. 技术选型

| 层级       | 选型                                                  | 目的                                            |
| ---------- | ----------------------------------------------------- | ----------------------------------------------- |
| 桌面容器   | Electron                                              | 提供 Windows 桌面窗口、原生文件对话框及文件操作 |
| 构建       | electron-vite + electron-builder                      | 统一主进程、预加载层、界面构建与安装包生成      |
| 界面       | React + TypeScript strict                             | 组件化界面与明确的数据契约                      |
| 编辑器     | CodeMirror 6                                          | 成熟的文本编辑、Markdown 高亮、历史和搜索能力   |
| Markdown   | unified + remark-parse + remark-gfm + remark-rehype   | 建立可扩展且一致的解析流程                      |
| 渲染处理   | rehype-sanitize + rehype-highlight                    | 过滤不安全内容并提供代码高亮                    |
| 样式       | CSS Modules + CSS 变量                                | 控制样式范围，统一主题、间距和字体              |
| 状态管理   | React hooks，按文档与偏好拆分                         | 保持首版状态模型简单                            |
| 检查与测试 | ESLint、Prettier、Vitest、Testing Library、Playwright | 覆盖代码质量、关键逻辑、交互和桌面流程          |
| 包管理     | npm + package-lock.json                               | 使用一致依赖安装方式                            |

开始实现时选择互相兼容的稳定版本并提交锁文件，不在正式依赖中使用浮动的 `latest`。开发文档记录实际 Node.js LTS 与 Electron 版本。

## 5. 架构与目录约定

```text
src/
  main/                  # 窗口生命周期、原生对话框、文件读写、恢复数据
  preload/               # 暴露最小化、具备类型的桌面 API
  renderer/
    components/          # 通用界面组件
    features/
      document/          # 文档状态与文件操作交互
      editor/            # CodeMirror 集成
      preview/           # Markdown 渲染与文章目录
      settings/          # 主题、字号、偏好
    styles/              # 全局基础样式与设计变量
  shared/                # IPC 契约、共享类型、可复用纯函数
tests/
  fixtures/              # Markdown 样例与异常文件
  e2e/                   # Electron 关键流程测试
docs/                    # 开发规范、架构说明、验收记录
```

- 主进程负责文件系统，渲染进程负责界面，预加载层只做受控桥接。
- `shared` 不依赖 Electron 或界面组件；业务模块避免相互循环引用。
- 文档模型至少包含文档标识、文件关联、正文、编辑版本、已保存版本、原始编码与换行、磁盘基线和错误状态。
- 未保存状态统一由当前正文与最近成功保存的正文比较推导；版本号只用于异步写入排序，不能单独决定是否有修改。保存期间继续编辑时，以本次实际落盘的内容更新基准。
- 编辑器文档是编辑正文的权威来源，应用状态与预览按版本同步；避免每次输入重建编辑器实例或复制多个大文档状态。
- 文件保存采用同一文档串行队列；旧的保存结果不能覆盖较新的编辑状态。
- 预览通过 Markdown 语法树生成目录和锚点，不使用正则表达式解析整篇 Markdown。
- 只有出现实际性能问题时再引入 worker、额外状态库或其他基础设施。首版实测发现极长连续段落排版会占用界面线程，因此对超过 150,000 个字符的文档使用 Web Worker；内容变化时终止过期任务，保持预览与当前文档一致。

## 6. 文件可靠性规范

### 6.1 打开与保存

- 首版支持 UTF-8，能够识别并保留 UTF-8 BOM；新文档默认无 BOM 的 UTF-8。
- 对不能可靠按 UTF-8 解码的文件明确提示暂不支持，避免以乱码覆盖原文件。
- 读取时记录原文件的 LF / CRLF；保存保留原换行方式，新文档默认 LF。混合换行文件保存时统一为检测到的主要换行方式，并提示该变化。
- 保留文档末尾是否有换行，不在保存时偷偷格式化整篇文件。
- 使用同目录临时文件写入并替换目标文件；临时文件写完前不得破坏原文件。替换失败保留原文件并报告错误。
- 文件读写失败、权限不足、磁盘空间不足等情况必须显示可理解的错误，并保留内存中的编辑内容。
- 保存期间继续编辑时，以本次实际落盘的正文更新保存基准；后续正文与其不同时显示未保存，还原一致时恢复干净状态。
- 保存已有关联的文件前检查磁盘基线；检测到外部修改时提供重新载入、另存为、明确覆盖三种操作，禁止静默覆盖。
- 外部变更检测不得只依赖文件监听：同时使用时间、大小和必要时的内容校验。首版不承诺跨进程锁定，检查与写入间的极短竞争窗口需记录为已知限制。
- 关闭标签和退出时，只对存在实际内容差异的文件提供保存、放弃、取消；保存失败或另存为取消时，原操作不得继续。新建、打开、拖入与切换文件不丢弃其他标签，也不触发其保存确认。

### 6.2 恢复草稿与偏好

- 首版“自动恢复”保存的是恢复草稿；用户文档由显式保存操作写入。
- 内容变更后约 2 秒保存恢复草稿，草稿写入也需避免半写入状态。
- 草稿关联原文件与磁盘基线；异常退出后提示恢复，不能直接覆盖磁盘原文。
- 多标签草稿按文档独立判断并汇总持久化；保存、还原或关闭一个文件不能清除其他文件草稿。异常退出后可恢复所有脏文档，并兼容旧版单文档草稿。
- 用户明确放弃修改后清除相应恢复草稿。
- 草稿与偏好存放于 Electron `userData` 目录，不放入用户文档目录或源代码仓库。
- 偏好数据带版本号；读取失败时使用默认值，不阻止应用启动。

## 7. 内容与进程安全边界

- Electron 开启 `contextIsolation` 与沙箱，关闭 `nodeIntegration`；不向界面暴露通用 IPC 或任意文件读写能力。
- IPC 接口按用途命名、具有明确输入输出类型，并在主进程校验参数、文档句柄及发送来源。
- Markdown 渲染使用固定的净化规则，不执行脚本、事件属性或原始 HTML；代码内容始终作为文本处理。
- 只允许受支持的链接协议；HTTP/HTTPS 链接在系统浏览器中打开，应用窗口不导航到外部网页。
- 本地相对图片以当前文档目录为基准；通过受控资源协议加载，规范化路径并校验最终路径，处理 `..`、编码绕过与符号链接越界。
- 首版本地图片限定为文档目录及其子目录中的 PNG、JPEG、GIF、WebP；不直接开放任意 `file://` 或本地 SVG。越界或不支持的资源显示占位说明。
- 远程图片默认不加载，用户可在阅读设置中启用；核心编辑与阅读功能不依赖网络。
- 配置与实际资源策略匹配的 CSP；不引入远程脚本、字体或 CDN 依赖。
- 应用日志不记录 Markdown 正文、草稿内容或其他敏感用户数据；错误诊断避免输出完整个人路径。

## 8. 编码与变更规范

- TypeScript 开启严格模式；避免 `any`，外部输入先作为 `unknown` 校验。
- React 组件使用 PascalCase，hooks 以 `use` 开头，函数与变量使用 camelCase。
- 业务函数命名表达行为；优先拆分过长组件与混合职责，不设机械的文件行数上限。
- 异步调用有错误处理、取消或过期结果控制；事件监听、定时器、编辑器实例在生命周期结束时释放。
- 注释解释原因和约束；对外 API、文件保存与恢复流程保留必要说明。
- 界面文案集中维护，用户可见文本默认简体中文；代码标识使用英文。
- 间距、颜色、字号、圆角使用统一 CSS 变量，不在组件中重复定义主题色。
- 不为未提出的需求提前搭建通用平台，不添加无法解释用途的依赖。
- Git 提交按清晰的小改动组织，建议使用 `feat:`、`fix:`、`docs:`、`refactor:`、`test:`、`chore:` 前缀；提交前查看差异。
- `.gitignore` 排除 `node_modules`、构建目录、安装包、日志、恢复数据与本地环境文件。

## 9. 性能目标

以下是开发验收目标，不代表当前已有测量结果。首个可运行版本须记录 Windows 测试机器的 CPU、内存、系统版本及实际结果。

| 场景     | 目标                              | 测量口径                                                                                     |
| -------- | --------------------------------- | -------------------------------------------------------------------------------------------- |
| 冷启动   | 3 秒内可交互                      | 安装后的生产构建，从启动进程到欢迎页或编辑器可响应                                           |
| 常规文档 | 100 KB、约 2,000 行输入无明显卡顿 | 包含中文、代码与表格，记录输入到界面更新的延迟                                               |
| 实时预览 | 停止输入后约 300ms 内更新         | 常规文档，采用约 150ms 防抖，并丢弃过期渲染结果                                              |
| 大文档   | 1 MB、约 20,000 行在 2 秒内可操作 | 不含嵌入式图片数据，分别记录界面可操作与完整预览时间；复杂文档在后台排版，完成前显示进度状态 |
| 较大文件 | 超过 5 MB 提示并允许选择继续      | 默认进入编辑模式，预览由用户按需开启                                                         |

对超过基准的复杂文件优先保证编辑和保存可用；长篇渲染不得造成输入丢失。性能结果使用生产构建，重复测量并记录中位数和最慢值，不使用开发服务器结果代替。

## 10. 测试与验收

### 10.1 测试策略

- 单元测试覆盖真实风险：编码与换行、标题锚点、净化、路径校验、脏状态、版本化保存和冲突判定。
- 交互测试覆盖新建、模式切换、未保存弹窗、查找替换和错误反馈。
- Electron 端到端测试覆盖打开、编辑、保存、重新打开、关闭取消和恢复草稿；仅在临时目录使用测试文档。
- Windows 实机手工检查中文输入法、文件锁定、安装包启动、键盘导航、主题与缩放。
- 不为纯样式调整添加重复实现逻辑的测试；安全边界与文件可靠性变更必须有针对性验证。

### 10.2 固定验收样例

样例集至少包含：六级标题、重复中文标题、嵌套列表、任务列表、引用、表格、删除线、带语言标识的代码块、超长行、相对图片、图片缺失、外部链接、原始 HTML、恶意脚本链接、空文档、UTF-8 BOM、LF/CRLF、非 UTF-8、混合中英文以及大文档。

### 10.3 首版必须通过的流程

1. 新建中文文档，输入标题、列表、代码和表格，实时预览正确，保存后重新打开内容一致。
2. 在中文输入法组合过程中切换候选词，输入不丢失、不重复，快捷键不抢占候选选择。
3. 修改文档后关闭窗口，选择取消仍保留内容；选择保存但保存失败时仍保留窗口和修改。
4. 应用外修改已打开文件，应用内保存时能检测冲突；另存为不会覆盖外部更新。
5. 连续编辑并快速保存，不出现旧保存结果把新内容标成已保存的情况。
6. 恢复草稿写入后异常终止进程，重新启动可恢复最近已落入草稿的内容；恢复前不改写原文件。
7. 阅读长文并调整字号、目录和主题，正文无溢出，代码与表格可单独横向滚动。
8. Markdown 中的脚本、事件属性和危险链接无法执行，本地图片无法读取许可目录之外的文件。
9. 断网后安装包仍能完成新建、打开、编辑、预览和保存。
10. Windows 路径包含中文、空格或特殊字符时，文件和相对图片处理正确。
11. UTF-8 BOM、LF/CRLF 和末尾换行往返保存符合约定；非 UTF-8 文件不能被误保存覆盖。
12. 仅用键盘完成打开、编辑、查找、保存和关闭，焦点始终可辨认。

### 10.4 完成定义

实现阶段需提供以下脚本约定：`dev`、`lint`、`format:check`、`typecheck`、`test`、`test:e2e`、`build`、`dist:win`。

每项功能完成时，应满足：验收条件通过、相关检查通过、无新增未处理错误、必要说明更新。发布首版前再执行完整检查、Windows 安装包冒烟测试与性能测量。交付记录列出真实测试结果、未执行项及原因，不将计划中的检查表述为已通过。
