# 墨页 0.2.4 验收记录

日期：2026-11-21。本次修复 Windows 仍从旧目录启动墨页的问题。应用启动参数和单实例功能的实现与测试记录见 [0.2.3](验收记录-0.2.3.md)，右键菜单与紧凑布局见更早版本记录。

## 根因与修复

Windows 实际默认程序是 `Applications/墨页.exe`，其打开命令仍指向原 `release/win-unpacked/` 中的 0.1.0。用户已经安装 0.2.3，该版本的 `Moyan.Markdown` 注册正确，但 Windows 保留的原有应用选择仍使用另一条旧命令。通过 [AssocQueryStringW](https://learn.microsoft.com/en-us/windows/win32/api/shlwapi/nf-shlwapi-assocquerystringw) 查询实际命令、可执行文件与 ProgID 确认，不把 `.md` 默认注册项单独作为系统实际选择的依据。

本次已在用户授权的修复范围内，将当前用户墨页自身的 `Applications` 启动命令修正为已安装的 0.2.3 路径，保留用户选择墨页这一设置，并通知 Shell 更新关联缓存。旧命令的备份位于本地忽略目录 `.runtime/default-association-backup.json`；不在仓库中记录本机安装绝对路径。

安装包 0.2.4 增加 `build/installer.nsh`：

- 安装和升级同步注册 `Applications/墨页.exe` 的打开命令、友好名称及 `.md` / `.markdown` 支持类型。
- 可执行文件路径与 `%1` 参数分别加引号，兼容中文及空格路径；保留由 Windows 维护的用户默认选择。
- 卸载前比较当前打开命令，只清理仍属于本安装位置的应用注册；另一位置或后续安装已接管时保留它。
- 沿用 0.2.3 的文件参数、请求排队、文件校验和单实例实现，无新增运行依赖或常驻轮询。

Windows 应用注册依据：[Microsoft 应用注册文档](https://learn.microsoft.com/en-us/windows/win32/shell/app-registration)。本次自定义 NSIS 宏只更新墨页的应用注册，沿用已有文件类型注册。

## 实际系统双击验证

使用 computer-use 技能在资源管理器中操作本次创建的两份中文空格文件名的临时 Markdown 文件。验证前看到旧 0.1.0 欢迎页，将该无文档窗口正常关闭，再验证：

1. 双击第一份文件，启动已安装的 0.2.3，出现文件名标签、正确标题与正文，状态为“已保存”。
2. 回到资源管理器双击第二份文件，原窗口新增第二个标签并显示其正文；第一份标签仍存在。
3. 第二次双击后只有一个墨页窗口，窗口标识与第一次相同，实际应用路径为安装目录的新版。
4. 测试结束正常关闭仅含测试文档的墨页窗口，并将资源管理器恢复到原目录。没有编辑用户文档。

这次是实际资源管理器双击，补齐了 0.2.3 只验证 exe 文件参数而未检查本机默认关联的缺口。

## 交付与限制

- 版本 0.2.4，输出目录 `release/0.2.4/`，安装包 `Moyan-0.2.4-Setup.exe`；免安装程序 `win-unpacked/墨页.exe` 须保留整个目录。
- 本机已安装应用仍为 0.2.3，当前默认打开已修正并验证。没有执行 0.2.4 对用户安装目录的覆盖安装或完整安装卸载；新宏通过隔离 NSIS 探针验证。
- 选择其他默认应用仍由用户在 Windows 中完成；单独移动免安装目录时仍需重新指定该位置。
- 极长连续段落预览、中文输入法等历史限制与未完成的人工检查继续保留，见此前记录。
